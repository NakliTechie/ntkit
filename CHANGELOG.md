# Changelog

## [Unreleased]

### Added

- `evals/run.sh --runs N --without <path>`: an A/B mode that asks whether a rule or skill changes behaviour. Each case runs N times as checked out and N times with one change, a file or folder under `skills/` deleted or a `.patch` applied, so a single paragraph can be switched off. `evals/summary.py` reports each arm's pass rate per case, the cases that flipped in each direction, and mean turns, input, output and cache tokens, time and cost per arm. The mode measures and never gates (exit 0 whatever the rates). `--runs N` alone repeats plain runs. `--dry-run` prints the plan and the cost ceiling (runs × arms × each case's budget) and stops before any model call; a ceiling over `NT_EVAL_MAX_USD` (default $25) is refused. AUTHORING §11 says when to use it. `tests/eval-ab.test.sh` covers the argument checks, the ceiling and the summary. Ideas from Thorsten Ball's control-versus-treatment agent runs and the MiniMax Code team's `harness-experiment` skill (ideas only).
- `tests/public-paths.test.sh`: fails when a shipped file names a home-directory path or a personal folder layout; owners add their own private words through `NTKIT_PRIVATE_TERMS`, which the public test never names.
- `/lab-nt` blockers are work (from a GPU inference-engine project's decode campaign, 2026-10-24/25, where one pre-existing OLMoE gate failure blocked every keep for a night). New `bin/lab.py baseline <dir> [--failures ID..]` records the gate failures seen on the start commit; `keep --gate known --failures ID..` keeps a candidate whose failures are all on that baseline and reverts on any new one. `references/contract.md` gates the start commit in Phase 0.5, asks gates to print why they failed and to carry near-tie rules for discrete choices, defines the leg clock as active time, and has the harness pause known background loads during a measurement. `references/loop.md` adds "Blockers are work": classify a repeated failure at its first repeat, fix within authority without asking, and for owner-only decisions write one question with a default and continue on a provisional branch. `references/ending.md` narrows PARKED to blockers with no path within authority, seals a successor campaign after an approved lock change, and applies reversible defaults at the next leg start. `tests/lab.test.sh`: 89 → 96 cases.
- `SUBSTANCE.md` §6.17 **Unexecuted gate**: a gate vouches only for code it executed, compared with an outside reference. `/lab-nt` `references/loop.md` requires a keep to show the gate reached every touched path; `references/contract.md` records each gate's inputs, paths and reference. From a GPU inference-engine project's prefill lab (2026-10-23), where an accuracy gate with short prompts passed a kernel change that broke every prompt over 256 tokens.
- `/lab-nt` surprise ledger and proposer ledger. `bin/lab.py predict <dir> <id> --proposer P --predicted V` records who proposed an experiment (provider/model or vault note path) and the metric they expect, before it runs, in the sealed state file. `keep` now takes a required `--id` and refuses an experiment with no prediction or with a result already recorded; it records the outcome, the actual metric (mean of `--cand`, or `--actual`, required with `--paired`) and the surprise (actual − predicted, sign kept, absolute value printed). New `record` logs experiments that never reach `keep` (blown cap, scope violation). New `summary [--leg N]` prints the surprise rate and ideas · measured · kept · high surprise per proposer, over the campaign and every child and fork. High surprise is |surprise| above `init --surprise X` (metric units), default 10% of the prediction. `references/loop.md` adds the predict step and treats a high-surprise failure as a finding; `ending.md` adds Surprise and Proposers lines to the leg report. State files from 2.7.1 (no `ideas` key) still load, check and summarise; only new experiments need a prediction. `tests/lab.test.sh`: 59 → 89 cases.

## [2.7.0] — 2026-10-22

### Added

- `/lab-nt` is recursive. **Downward:** a leg forks K fresh-context branches at one third and two thirds of its budget and continues from the best (fork-and-flush, arXiv:2610.07447: 0.78 against 0.47 for one run at equal compute), and an experiment may open a child campaign for a sub-question with its own metric, to depth 2, with its budget carved from the parent (at most half of what is left), its fence inside the parent's and every parent lock inherited. **Upward:** `/lab-nt meta <skill>` edits only `skills/<skill>/references/`, steers on a public suite and keeps an edit only when a private suite it never reads per task rises beyond noise (the AIDE² pattern, arXiv:2609.26457); with the user's per-campaign `merge: auto` grant it merges locally and logs the revert command, never pushing. The outer loop never reloads itself, so a candidate `/lab-nt` cannot rewrite the rules judging it. A **joint gate** makes a metric count only when the contract's gates (an accuracy batch, for example) pass on the same commit, and `device: shared` serialises forks and children and adds canary and interleaved-measurement rules (from a GPU inference-engine project's Phase 3, where other GPU users moved timings 2-4x). New `bin/lab.py` enforces what a script can: a sealed state file (a digest kept in the git directory, so a hand edit to the budget or merge grant is refused), lockbox hashes and new files in locked paths, the fence of the campaign and every ancestor against the leg's start commit (committed changes included), experiment budgets carved for children and forks (no refunds, no overshoot, N means N experiments), depth, the keep decision (KEEP exit 0, REVERT exit 4; noise required; paired needs 10 items), the leg odometer, the refusal to resume a STAGNANT or DRY-WELL leg with an unchanged contract, and the merge grant. Meta merges run from the lab's own worktree with the free tests, never in the main checkout. A cold review found 10 defects in the first draft (scope check missing committed changes, re-init re-hashing a tampered harness, an unprotected state file, budget off by one, glob mismatch, child fence, unlocked parallel forks, weak keep, unenforced re-arm rules, meta merge in the main checkout); all fixed with tests. `tests/lab.test.sh`; eval case `lab-nt-meta-needs-references` (not yet run: it costs a model run). `SKILL.md` becomes a router over `references/contract.md`, `loop.md`, `ending.md` and `meta.md`.

## [2.5.0] — 2026-10-02

### Added

- `/windup-nt` sweeps stray branches. `windup-nt/bin/branches.sh` classifies every local and `origin` branch and changes nothing: `merged` (an ancestor of the default branch, or a squash or rebase merge whose merge changes no file), `hold` (merged, but a long-lived name, a remote or same-name local branch with unmerged commits, or named in `pending.md` or `workplan.md`), or `unmerged`. ### Changed

- `/forward-pass-nt` tests live structure. The Stray lens adds three tests: no caller (callers outside the repo count), deletion (a pass-through is Stray), and two adapters (one implementation and no test stand-in is Stray). Security gains a fourth habit: a permission, flag or gate rule written in two places is a finding, ranked by what the weaker copy lets through. The map ranks files by churn, and structure items in busy files come first. A fix that would undo a recorded `history.md` decision quotes it and defers to `/decide-nt`.
- Dependency categories decide which stand-in a test may use (`test-value.md`, `SUBSTANCE.md` §6.3): the real code for in-process logic, a local stand-in for a database or filesystem, an injected port with a test adapter for owned remote and third-party services, the clock and randomness. A Stray item or refactor goal writes its end state in one sentence and deletes compatibility paths with no caller; its checker greps each deleted name for a remaining caller. Removing a published export, a persisted data shape, a public route, or a documented flag or config key is a new stop-line.
