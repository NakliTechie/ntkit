# Changelog

## v1.6.0 — 2026-09-23

- **Changed:** `package-nt`'s readiness gate now reads the README against the house shape (`README-DOCTRINE.md` in the naklitechie-doctrines reference: header · install before why · "use something else if" · commands · verify · license + pointers, ≤ 120 lines) instead of a presence check, and adds a **social preview** gate: `usesCustomOpenGraphImage` must be `true` on the repo, or every shared link renders GitHub's default card — a blocker. GitHub has no API for it, so Phase 2 now produces `marketing/social.png` (1280×640, the hero recut with the name and the one sentence) and the gate names the upload path. Earned from the ferrule v1.1.0 release: the README was rebuilt 245 → 119 lines and the repo turned out to have been on the default card since launch.

- **Fix:** `windup-nt`'s stray-worktree sweep deleted work. A worktree's `plan/` is gitignored, so it lives in that directory and nowhere else — no commit, no remote, no reflog — and `git worktree remove` takes it with the tree. Step 5 now rescues `plan/` into the main checkout before removing any worktree. Found the hard way: two `walkthrough-nt` reports and 51 screen recordings were destroyed this way in a single session, minutes after the runs that produced them.

- **Fix:** `release-nt` Phase 4 paired `git tag vX.Y.Z` with a `--follow-tags` push, which does not work: `--follow-tags` pushes **annotated** tags only, so a lightweight tag stays local while the push reports success, and `gh release create` then refuses with "tag exists locally but has not been pushed". Now tags with `git tag -a` and confirms the tag reached the remote with `git ls-remote --tags` before creating the release, rather than inferring it from an exit code. Hit while cutting two real releases.

- **Added:** `walkthrough-nt` Phase 5 gains **the amplifier** — the method that made every timing chase this week tractable. An intermittent failure cannot be fixed with confidence, because you cannot prove a fix against a bug that appears 3 times in 40 runs. Find the timing constant it depends on and exaggerate it until the failure is deterministic: one `setTimeout(fn, 0)` changed to `300` took a suite from 85/86 to 49/86 and a focused repro from 3-in-40 to 6-in-6, making the fix provable at 8-in-8 green. Then remove the amplifier and confirm at realistic timing.
- **Added:** the driver-suspect rule gains a third check — **confirm your edit landed where you meant.** A fix that appears not to work is often a fix that was never applied to the thing you think it was: a string replace matching an earlier occurrence, an edit to the source of a generated file without running the generator, a change in the wrong worktree. Earned from a run that put a CSS property on the first rule in the file instead of the intended one and read the resulting red as the fix being wrong.
- **Added:** **prove which change closed it** when you made more than one. Two edits and one green tells you nothing. A dogfood run's isolation matrix showed its product fix closed both failures alone, while its test-harness change alone also went green on one — for the wrong reason, by moving a key event earlier relative to the race and leaving the defect latent under a passing check.
- **Added:** Phase 6 forbids **a fixed sleep standing in for a condition**. `await sleep(60)` meaning "focus has returned" is a race by construction and every future timing flake arrives through it; wait on the observable with a timeout that fails loudly. Raising a sleep to clear a red is `SUBSTANCE.md` §6.7.
- **Changed:** `SUBSTANCE.md` §6.3 names the sharpest form of a tautological test — one written against a defect you just found, which goes green on today's broken behaviour and pins the bug as intended for the next reader. Delete it and record the gap.

- **Added:** `SUBSTANCE.md` §6.7 **re-run-until-green** — the seventh named reward-hacking pattern. Treating an unexplained red as noise and re-running until it passes yields a green that is evidence of nothing: either the check is nondeterministic, which is the finding, or a true signal was discarded. Names the dull common cause (a single-test red off a half-saved tree, a test landing a moment before the fix it asserts) and forbids absorbing an unread red with a retry, a timeout bump, or a skip — that is gate self-weakening with extra steps. Extends to any tool's silence: a search returning nothing on a file it refused to read is not evidence of absence. Cross-referenced from `STATES.md` guard 2, and from `walkthrough-nt`'s driver-suspect rule. Earned from a dogfood run where a "flake" reproduced deterministically on demand and 170 subsequent runs found no nondeterminism at all.

- **Added:** `walkthrough-nt` Phase 5, the **chaos leg** — a bounded random walk from the states the scripted journey already reached, with the Phase 3 invariants as the oracle. The scripted journey is one draw from one distribution written by the same mind that built the app; this covers the space between its steps (unexpected action sequences, timings, inputs). Budgeted (~40 actions or 5 min per role), declared in the report whether or not it yields, and skippable with a reason when the app has un-stubbed irreversible side effects. **A breach earns an ID only if it replays** from the action-log prefix; unreproduced breaches are listed as leads and counted separately, never folded into the finding totals. Confirmed findings are pinned as harness regression cases so the sequence pays every run, not once. Phases renumbered: Lever 4.5 → 6, Report 5 → 7.
- **Added:** `ux-review-nt` Phase 3, the **flail** — a bounded misclick-and-recover walk after the scripted journey, on the same rationale. Its finding class is **recoverability** (dead ends, lost work, unrecoverable state, traps, errors that don't say what to do), explicitly not crashes, which the invariant set already covers. ~15 min / ~30 interactions, declared or skipped with a reason. Read-only like the rest of the command.
- **Changed:** both walkthrough commands now **arm a named invariant set before the first interaction** instead of ambiently watching the console — `INV-EXC` (uncaught exception), `INV-REJ` (unhandled rejection), `INV-ERR` (`console.error`), `INV-HTTP` (4xx/5xx), extensible per repo, each breach producing a finding with an ID attributed to the beat that preceded it. Ported from Bombadil's zero-spec browser defaults. The armed list goes in the report header. `walkthrough-nt` fixes breaches; `ux-review-nt` reports them and routes to `/walkthrough-nt` — it stays read-only for crashes too. The set is also armed for every harness run, so a `verify` that drives the happy path while an exception fires underneath is no longer vacuously green.
- **Added:** both commands **record the run and keep an append-only action/beat log**, into `plan/<command>-<date>-run/` (gitignored), and hand the recording back with `SendUserFile`. Playwright's `recordVideo` context option on web (closed in a `finally`, or the file never lands), `asciinema`/`capture-pane` on TUI, `simctl io recordVideo` on iOS, an annotated transcript on CLI; a screenshot contact sheet is the declared fallback. The step narrative carries timestamps into the recording, and the log is what makes a finding replayable rather than described. For a reader who doesn't read diffs, watching the walk beats a summary of it.
- **Changed:** `ux-review-nt` becomes a **router** (AUTHORING §9) — a 2,861-word body split into `SKILL.md` (contract, guards, the read-only stop-line, the rotation rule, a six-row phase table) plus `references/{surface,cold-start,walk,flail,audit,report}.md`. Procedure text moved verbatim; nothing dropped. Same shape as its sibling `walkthrough-nt`.
- **Fix:** both commands named MCP servers their frontmatter didn't permit — `ux-review-nt` calls for Chrome DevTools MCP (Lighthouse) and Chrome MCP (WebGPU beats), `walkthrough-nt`'s boot detail for "a browser MCP" and the Chrome MCP. `allowed-tools` now carries them, plus `SendUserFile` for the recording handback. Driving a browser via Bash + Playwright was always allowed and stays the default path; this only closes the gap for the named servers.

- **Changed:** `ux-review-nt` now covers four surfaces, not just browser — CLI, TUI, and native (macOS/iOS) via a new Phase 0 surface detection (explicit override or repo-signal inference), per-surface cold-start recipes in Phase 1, and a per-surface objective-audit swap (Phase 4 after the renumbering below) (Lighthouse stays web-only; native/iOS gets a real automated a11y audit via `XCUIApplication().performAccessibilityAudit()`; CLI gets a scripted `--help`-coverage + error-message-quality health check; TUI gets a yes/no/partial checklist). `allowed-tools` gains `mcp__computer-use__*` and the iOS Simulator tool. Only one surface (native/iOS) gets a real score; CLI/TUI are explicitly labeled checklists, not scores, so the report never blurs the two.
- **Added:** [`MEMORY.md`](MEMORY.md) — the `plan/` memory contract. Splits the folder into **records** (append-only: reports, summaries, `soc.md`) and **derived** files (`pending.md`, `workplan.md`, `history.md`'s indexes) that are a projection over them, so the plan can be rebuilt from the log. Five writer rules (the human writes anywhere; agents append to records, may flip the status of an item they did the work for, and may not add/drop/re-rank/re-word — that belongs to `/replan-nt`, `/windup-nt`, and `/scaffold-nt`; a goal is recorded, never self-authored into the shared plan). Record files declare an `## Impact`; derived items carry `[from: <record>]` provenance. Surfaced as guard 5 in [`STATES.md`](STATES.md) and §8.5 in [`AUTHORING.md`](AUTHORING.md).
- **Added:** `plancheck` (`skills/replan-nt/bin/plancheck.py`) — a mechanical replay check over a `plan/` folder. Reports **orphans** (a derived item whose provenance names no record) and **ghosts** (a record declaring an `add` impact nothing cites); untagged items are info, not failure. Stdlib only, never calls a model, never edits anything. Exit 0 clean / 1 divergence / 2 could not run; `--since` and `--json`. `/replan-nt` Step 4.5 now runs it instead of judging by reading, and falls back to the previous read-and-judge behaviour when it is absent.
- **Changed:** nine record-writing commands (`forward-pass`, `walkthrough`, `ux-review`, `maintain`, `live-check`, `harden`, `autopilot`, `windup`, `lab`) end their report with an `## Impact` section declaring what should change in the derived files, or `none — <reason>`.
- **Changed:** `autopilot-nt` given a prose goal now records it verbatim and queues it **in its own run record**, not as checkboxes in `plan/workplan.md`, and never edits the goal mid-run — an agent that authors the criteria it is judged against can meet them by editing. Its `writes:` contract narrows to status flips on items that already exist. `harden-nt` likewise routes deferrals through an `## Impact` line instead of writing workplan items directly.
- **Fix:** `plancheck` no longer reads a format placeholder written in prose (`[from: <record>]`) as a real provenance tag and reports it as an orphan. Angle brackets never appear in a record slug, so such a line counts as untagged. Found by dogfooding the checker on a project whose decision log documents the tag grammar.
- **Fix:** `plancheck` reads numbered list items, not only `-`/`*` bullets. `pending.md`'s `## Now` section is commonly an ordered list, and an item that did not parse was an item whose provenance was never checked. Found by dogfooding on a project whose Now section is numbered.
- **Compatibility:** additive, not a migration. An untagged derived item means hand-written, so every existing `plan/` folder passes unchanged (verified: 161 items across three real repos, exit 0).

- **Changed:** `capture-nt` Step 2 becomes an orient step run *before* fetching — duplicate check, nearby notes to link against, and tag-reuse suggestions — so a source the vault already holds is never re-fetched, and new notes reuse existing tags instead of coining novel ones. `ask-nt` Step 2 leads with ranked search rather than an unordered file list, and names the keyword-search ceiling explicitly. Both use the vault's optional `bin/vaultdb.py` index when present and fall back to the previous `rg` behaviour when it is absent.
- **Changed:** ATTEST formatting applies only to designated formal outputs exceeding approximately 200 unformatted characters. Ordinary conversation and shorter outputs use natural prose; evidence standards and execution permissions remain unchanged.
- **Fix:** `capture-nt` stages explicit capture-owned file paths and commits only those paths, preserving unrelated staged changes.
- **Added:** `package-nt` launch gate checks for a first-run guided tour (the spotlight walkthrough per the Build Doctrine's Surface conventions, driven by the vendored `tour.js`) — a nice-to-have, not a hard blocker.

- **Added:** `ATTEST.md` Issue 0.2, a **readability zone** alongside the original claim zone. Issue 0.1 only closed the claim zone (reserved/banned words, evidence classes) and gated even that behind a ~200-character formal-output threshold — below it, natural prose had no sentence-level discipline at all, which is where "walls of text" actually came from. Now a 25-word sentence cap, one-idea-per-sentence, active voice, and a banned-phrase list apply everywhere, formal or not; the threshold only gates typed-block structure. Added a closed lexicon of documented AI-writing tells (significance inflation, copula avoidance, promotional adjectives, rhetorical "not just X but Y" parallelism, and seven more categories), sourced from Wikipedia's "Signs of AI writing" and published LLM word-frequency studies rather than the standard's own ≥3-transcript change-form process — logged as an explicit governance exception rather than a silent one. `attest-100-spec-001.md` (the full reference spec) moved into the repo from `~/Downloads` and reconciled to match.
- **Added:** `forward-pass-nt` and `harden-nt` gain `references/security-classes.md`, condensed from [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill) (MIT) — all ten of its attack-class domains (universal classes, AI/agents, web/auth, client-side, cloud/deployment, memory-safety/binary, desktop/mobile/local-IPC, protocols/RPC, resource-exhaustion, data-isolation), not just a web-only subset, ahead of a shift toward distributed binaries and end-user apps. `forward-pass-nt`'s Security lens links to it for security-sensitive apps; `harden-nt`'s adversarial rounds use it as a per-agent brief instead of a blank-page prompt. `forward-pass-nt`'s ranking also gained the source's severity discriminator (does a result *fully defeat* a control, or only weaken it?) and its five anti-patterns for what isn't a security finding. `maintain-nt` and `live-check-nt` each got a narrower slice (CI/supply-chain drift; live response-header checks).
- **Added:** `reclaim-nt` — sweeps a project for orphaned model checkpoints, stale downloads, and dead build artifacts that accumulate on disk over a project's life. Read-only by default: ranks candidates by confidence (already consolidated elsewhere, duplicate, unreferenced, project-stale) and deletes nothing without an explicit per-item `apply <id>`. The kit is 23 skills.
- **Changed:** README rebuilt to `README-DOCTRINE.md`'s house shape (156 → 109 lines): Install before Why, an honest "use X instead" paragraph, Commands as one aligned fenced block instead of a table, and a Verify-it-yourself section whose command was checked against the repo before being written down. The architecture/principles sections (state machine, report format, DRIVER/MEMORY/SUBSTANCE prose) collapsed into a single pointers line — the docs are unchanged, just no longer duplicated. The knowledge vault moved from a cramped footer line to its own product section and its own full-width bar in the workflow diagram. The diagram's START and OPEN phases merged (five phases now, not six); regenerated `workflow.png` and `social.png` from the updated `workflow.svg`, and re-uploaded the social preview live on GitHub.
- **Fixed:** `package-nt`'s social-preview instruction was "drive the UI via Claude-in-Chrome," with no procedure. Replaced with `references/social-preview.md`, written from actually doing it: the visible "Edit" button opens a safe dropdown, but its "Upload an image…" item is itself a native file-input trigger, and clicking it opens an OS picker the browser tool can't see — the file has to go in via `file_upload` against that control's ref instead. Also notes that `usesCustomOpenGraphImage: true` doesn't mean the image is *current* (no hash/date is exposed, so re-upload after every asset regen) and that the control auto-saves with no Save button, so a page reload is the real confirmation, not the first screenshot.
- **Added:** `forward-pass-nt` gains a fifth lens, **agent-readiness** (`AR` track, its own dedicated report section like Stubs), checking whether a declared agent-facing manifest exists at all, `manifest ⊇ command bus` parity against the UI (Build Doctrine's "two doors, one core"), staging on mutating/irreversible entries, `DRIVER.md`'s eight-point ergonomics self-check, and caller attribution. `harden-nt` was originally meant to test for this and add a surface where missing; it evolved into an adversarial path-hardening harness for a surface that already exists instead — left its behavior alone and added one line naming that boundary rather than implying it does something it doesn't. `scaffold-nt`'s seeded DRIVER-pass workplan item gained a sibling naming the manifest requirement itself; `package-nt`'s launch gate now blocks on agent-face presence and parity, per `DRIVER.md`'s own "run it again before public release" line. Fixed a pre-existing typo in `lenses.md` along the way: Phase 2's own heading said "three lenses" while the prose already listed four.
